# 🎨 신한 딜리버리 화면 디자인 통일 및 컴포넌트 정리 발표

> **발표 대상:** 이해진 
> **한 줄 요약:** 제각각이던 화면 디자인을 하나로 맞추고, 색상 토큰 및 컴포넌트들을 정리하여 개발 속도와 품질을 크게 향상

---

### 📌 [Slide 1] 디자인 시스템이란 무엇인가?

* **슬라이드 제목:** `디자인 시스템의 정의와 필요성`
* **디자인 시스템이란?**
  * • 서비스를 만들 때 필요한 **디자인 규칙(색상/폰트)**과 **재사용 가능한 부품(버튼/입력창 등)**을 하나로 모아둔 **'표준 가이드라인'**
* **디자인 시스템이 제공하는 3가지 핵심 가치**
  * • **1. 일관된 사용자 경험 (Consistency)**: 어느 화면을 가더라도 같은 브랜드 느낌과 조작감을 제공
  * • **2. 개발 생산성 향상 (Productivity)**: 디자이너와 개발자가 매번 처음부터 만들지 않고 만들어진 부품을 조립
  * • **3. 쉬운 유지보수 (Maintainability)**: 디자인이 변경될 때 중앙 규칙집 한 곳만 수정하면 서비스 전체에 즉시 반영
* **신한 딜리버리 목표:** `HTML / CSS / Thymeleaf 환경에 최적화된 통합 디자인 시스템 구축`

---

### 💡 [Slide 2] 왜 이 작업을 했나요? (기존 문제점과 목표)

* **슬라이드 제목:** `기존의 문제점 및 개선된 모습`
* **기존 문제점 vs 개선된 모습:**

| 구분 | 기존 문제점 (Before)  | 개선된 모습 (After)  |
|--------|--------------------------|-----------------------------|
| **1. 디자인 파편화** | 페이지마다 색상 톤이 조금씩 다르고 글씨 크기 규칙이 없어 비일관적임 | 공통 규칙을 적용되게 하여 전 화면 디자인 통일화 |
| **2. 비효율적 개발** | 새로운 화면을 만들 때마다 똑같은 버튼과 코드 구조를 매번 새로 작성함 | 이미 정의된 컴포넌트를 갖다 붙이기만 하면 3초 만에 완성됨 |

### 🏗️ [Slide 3] 어떤 구조로 만들었나요? (쉬운 설명)

* **슬라이드 제목:** `2가지 핵심 구조`
* **2가지 핵심 구조:**
  * • **1. 디자인 토큰 (Design Tokens)**: 색상, 글씨 크기, 여백을 코드 형태의 변수로 관리하여 한 곳만 바꾸면 앱 전체 디자인이 일괄 변경
  * • **2. 공통 프래그먼트 부품 (UI Fragments)**: 버튼, 배지, 입력 폼 등 반복 사용되는 UI를 29개의 컴포넌트로 정의하여 일관성 유지

* **화면이 만들어지는 방식:**
  ```
  [사용자가 화면 요청] 
         ↓
  [서버에서 이미 만들어둔 컴포넌트들을 착착 조립] 
         ↓
  [완벽하게 완성된 깔끔한 화면을 바로 보여줌]
  ```

### 🛠️ [Slide 4] 어떤 문제가 있었고 어떻게 해결했나요?

* **슬라이드 제목:** `문제 해결 사례`

#### 1번째 문제: CSS 클래스명 충돌 및 스타일 오염 문제
* **문제:** 공통 컴포넌트의 CSS 클래스명이 특정 페이지의 개별 스타일과 겹치거나 부모 스타일의 영향을 받아 컴포넌트 디자인이 깨지는 현상 발생
* **해결:** 접두사(예: .sd-btn, .sd-card) 규칙을 도입하여 공통 컴포넌트의 스타일 독립성(캡슐화) 확보

#### 2번째 문제: 버튼/카드 등의 다양한 타입 파편화 문제
* **문제:** 버튼이나 카드의 크기(Large/Medium/Small), 상태(Active/Disabled/Loading), 색상(Primary/Secondary) 조합에 따라 중복 코드가 수십 개씩 늘어남
* **해결:** Thymeleaf 프래그먼트에 매개변수(th:fragment="btn(type, size, disabled)")를 적용하여 단 하나의 공통 템플릿으로 모든 형태를 동적 처리하도록 구조화

### 🚀 [Slide 5] 느낀 점과 앞으로의 계획

* **슬라이드 제목:** `잘한 점과 앞으로의 발전 방향`

* **Keep (잘한 점)**
  * 색상과 글씨 규칙을 잘 정해두어서 UI/UX 전체의 디자인 완성도 향상
  * 만들어둔 컴포넌트를 갖다 쓰기만 하면 되니 새로운 화면 제작 시 소요 시간 하락

* **Problem (아쉬운 점)**
  * 화면의 연동성이 부족하여 색상 토큰을 정해두어도 미묘하게 다른 톤이 느껴짐
  * 컴포넌트 위치가 각 페이지마다 통일되어 있지 않아 확실한 위치 정의 필요

* **Try (앞으로 도전할 점)**
  * 어두운 화면(다크 모드)으로 바뀌는 컴포넌트를 추가하여 서비스에 대한 긍정적인 리뷰 향상 기대
  * 공통 스타일 변경 시 화면 깨짐을 자동으로 감지하는 시각적 회귀 테스트 도입

> **💡 한 줄 결론:** "표준화된 디자인 시스템 구축을 넘어 자동화와 테스트 프로세스를 붙여 디자인 시스템을 지속 가능한 구조로 발전 가능성 향상"
