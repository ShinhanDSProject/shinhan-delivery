## 📑 슬라이드별 구성 안 & 발표자 대본 (Master Script)

### 📌 [Slide 1] Intro: 사전 기획(MVP/화면설계) 기반 AI 페어 프로그래밍 개발 플로우

#### 🖼️ PPT 슬라이드 디자인 및 구성 요소
* **슬라이드 제목:** AI 시대의 개발 혁신: 사전 기획 기반 이슈 자동화와 AI 페어 프로그래밍
* **화면 배치:**
  - **좌측:** 사전 기획(MVP 기획서, 화면 설계서) ➔ GitHub Issue ➔ AI 연동 ➔ 자가 치유 4단계 프로세스 카드
  - **우측 하단 (수치 강조 박스):** `보일러플레이트 90% 단축`, `비즈니스 기능 개발 속도 5배 향상`

#### 🎤 발표자 입말체 대본 (Speaker Script)
> "안녕하십니까, 신한 딜리버리 프로젝트 발표를 맡은 테크 리드 [발표자 이름]입니다.
> 
> 저희 팀은 이번 프로젝트에서 Antigravity와 같은 AI 코딩 에이전트를 개발 동료이자 부사수로 도입하여 개발 프로세스 전체를 혁신했습니다.
> 
> 단, 저희는 AI에게 무작정 코딩을 맡기지 않았습니다. 개발 시작 전 **1. MVP 기획서**와 **2. 화면 설계서**를 선제적으로 완벽히 정의한 후, 이를 바탕으로 GitHub Issue를 발행했습니다. 
> 
> 이후 개발자가 `/plan` 지침으로 이슈를 지시하면 AI가 기술 영향도를 자동 분석하여 기획안을 작성하고, 개발자 승인을 거쳐 백엔드 비즈니스 로직과 프론트엔드 연동 코드를 즉시 연속 구현하도록 단일 통합 개발 파이프라인을 구축했습니다.
> 
> 그 결과, 반복되는 상투적 코드 작성 시간을 90% 단축시켰고, 신규 비즈니스 기능을 개발하는 전체 속도를 무려 5배나 향상시키는 놀라운 생산성을 경험했습니다."

### 🔍 [Slide 2] Phase 1: 화려한 성공 뒤의 솔직한 팀원 고충 & 5대 현실 결함

#### 🖼️ PPT 슬라이드 디자인 및 구성 요소
* **슬라이드 제목:** 현실의 반전: 팀원들이 겪은 4대 인적 고충과 5대 기술적 설계 결함
* **화면 배치:**
  - **상단 카형 박스 (인적 고충):** `AI 도구/컨벤션 피로도`, `코딩 근육 퇴화 & 메타인지(내가 뭘 모르는지) 상실`
  - **하단 비교 표 (기술 결함):** `UX (Thymeleaf SSR 외면 CSR AJAX 남용 0.5초 FOUC)`, `FE (HTML/CSS/JS 인라인 오염)`, `BE (계층 위반)`

#### 🎤 발표자 입말체 대본 (Speaker Script)
> "하지만, 이 화려한 5배 속도 향상의 그늘 뒤에는 생각지도 못한 치명적인 반전과 팀원들의 솔직한 고충이 기다리고 있었습니다.
> 
> 첫째로 인적 고충이었습니다. AI가 정답 코드를 1초 만에 뚝딱 내놓자, 개발자 스스로 고민하는 **'뇌의 코딩 근육'이 퇴화**하기 시작했습니다. 팀원들 사이에서는 *'AI 없이는 코드 한 줄도 못 짜겠다'*, *'내가 뭘 모르는지도 모르겠다'*라는 무력감과 창의력 저하 호소가 쏟아져 나왔고, 방대한 컨벤션 문서 속에서 핵심 우선순위를 놓치는 정보 과부하가 발생했습니다.
> 
> 둘째로 기술적 설계 결함이었습니다. 대표적으로 저희 프로젝트에는 **Thymeleaf라는 훌륭한 SSR 템플릿 엔진이 도입**되어 있었음에도, AI는 SSR 사전 바인딩 기능을 무시하고 빈 HTML을 리턴한 뒤 client-side AJAX 통신만 남발하는 CSR 방식을 양산했습니다. 개발자가 렌더링 흐름에 대한 제어권을 잃자, 사용자 화면이 0.5초간 텅 비거나 깜빡이는 **FOUC(Flash of Unstyled Content)** 현상이 방치되는 결함이 발생했습니다.
> 
> 저희는 깨달았습니다. 사람이 직접 기술적 의사결정을 내리지 않으면, AI의 속도는 결국 아키텍처의 파손으로 이어진다는 사실을 말입니다."

### 🛠️ [Slide 3] Phase 2: 아키텍처 재정립 & 코드 작성 후 '자가 치유 피드백 루프' 구축

#### 🖼️ PPT 슬라이드 디자인 및 구성 요소
* **슬라이드 제목:** 시스템적 해결: 사전 설계 준수 & 자가 치유 피드백 루프 구축
* **화면 배치:**
  - **중앙 (Mermaid 다이어그램):** `기획/설계` ➔ `이슈` ➔ `구현` ➔ `./scripts/verify.sh 검증` ➔ `실패 시 에러 로그 수집/AI Auto-Fix` ➔ `그린 빌드 커밋`
  - **우측 성과 지표:** `Thymeleaf SSR 사전 바인딩 0ms (Zero FOUC)`, `HTML/CSS/JS 3-Tier 분리로 중복 332줄 제거`

#### 🎤 발표자 입말체 대본 (Speaker Script)
> "저희는 이 문제를 시스템과 아키텍처로 정면 돌파했습니다.
> 
> 먼저 프론트엔드에서는 AI의 무분별한 CSR AJAX 패턴을 걷어내고, **Thymeleaf SSR 사전 바인딩(`th:each`)**으로 전환하여 초기 진입 지연을 **0.5초에서 0ms로 단축, FOUC 현상을 100% 완전 차단**했습니다. 또한 대용량 인라인 코드를 독립 static 파일로 3-Tier 분리하여 중복 코드 332줄을 제거하고 브라우저 캐싱 혜택을 확보했습니다.
> 
> 백엔드에서는 코드 작성 즉시 구동되는 **'자가 치유 피드백 루프(Self-Healing Loop)'**를 구축했습니다. AI가 코드를 작성하면 `./scripts/verify.sh` 테스트 하네스가 즉시 구동되어 Spotless 포맷팅, Checkstyle, ArchUnit 레이어 검증, JaCoCo 60%+ 커버리지, 400개 전체 테스트를 전수 검사합니다.
> 
> 만약 린트나 테스트가 하나라도 실패하면, 하네스가 에러 로그를 수집하여 AI에 즉시 피드백을 전달하고, AI가 수초 내로 스스로 원인을 진단하고 수정(Auto-Fix)하여 **100% 그린 빌드(0 Exit Code)** 상태가 확보될 때까지 피드백 루프가 자동 회전하도록 완성했습니다."

### 🎯 [Slide 4] Phase 3: AI와 협업할 때 개발자가 반드시 사수해야 할 4대 핵심 수칙

  - **상단 강조 캘아웃:** `💡 AI는 "구현(How)"의 부사수일 뿐, "품질과 방향성(What & Architecture)"은 사람의 몫`
  - **4대 수칙 카드:** 1. 선(先)기획 & 사람 주도 의사결정, 2. HTML/CSS/JS 3-Tier 파일 분리, 3. Thymeleaf SSR/CSR 렌더링 역할 분담, 4. Harness-First 0 Exit Code

#### 🎤 발표자 입말체 대본 (Speaker Script)
> "저희 팀의 시행착오와 성공 경험을 바탕으로, AI 시대에 개발자가 주도권을 쥐기 위해 사수해야 할 4대 핵심 수칙을 정립했습니다.
> 
> **첫째, 선(先) 기획 및 사람이 직접 기술적 의사결정을 주도해야 합니다.** 개발 전 MVP 기획서와 화면 설계서를 사람이 선제 정의하고 아키텍처 방향성을 지시해야 합니다.
> 
> **둘째, 프론트엔드 HTML/CSS/JS 3-Tier 파일 분리와 모듈화를 강제해야 합니다.** AI가 편리함 때문에 템플릿 파일 내에 인라인으로 코드를 섞지 못하도록 역할을 독립시켜야 합니다.
> 
> **셋째, Thymeleaf SSR과 CSR AJAX 렌더링의 역할을 명확히 분담해야 합니다.** 초기 0ms 화면은 서버가 사전 바인딩하고, 진입 후 동적 비동기 연동만 클라이언트가 맡도록 렌더링 흐름을 직접 설계해야 합니다.
> 
> **넷째, 정적 분석과 자동화된 하네스 통제망을 구축해야 합니다.** AI의 환각을 사람이 일일이 눈으로 검수하지 말고, `./scripts/verify.sh` 하네스를 통해 0 Exit Code 자가 치유 루프를 시스템으로 강제해야 합니다."

## ❓ 예상 Q&A 족보 3선 (심사위원 대비 답변 가이드)

### Q1. "AI가 만든 코드를 100% 신뢰할 수 없는데, 품질 검증은 어떻게 수행했나요?"
* **🎤 모범 답변:**
  > "저희는 AI의 출력 결과를 인간이 눈으로 일일이 검수하지 않고, 프로젝트에 구축된 `./scripts/verify.sh` Test Harness를 통해 자동 검증했습니다. AI가 코드를 작성하는 즉시 정적 분석(Spotless/Checkstyle), ArchUnit 단방향 아키텍처 검증, JaCoCo 60%+ 커버리지, 400개 전체 단위 테스트를 구동하며, 하나라도 실패 시 에러 로그가 AI에 즉시 전달되어 수초 내로 스스로 자가 치유(Auto-Fix)하여 100% 그린 빌드(0 Exit Code)를 달성한 무결점 코드만 커밋하도록 제어했습니다."

### Q2. "신입 개발자들이 AI에 너무 의존해서 기본기가 떨어지는 문제는 어떻게 해결하셨나요?"
* **🎤 모범 답변:**
  > "매우 핵심적인 지적입니다. 저희 팀 역시 초기에 AI가 정답 코드를 내놓자 직접 고민하는 '코딩 근육'이 퇴화하고 내가 뭘 모르는지조차 인지하지 못하는 메타인지 상실 문제를 겪었습니다. 이를 극복하기 위해 저희는 AI에게 질문을 던지기 전 30분간 개발자가 직접 고민하고 설계안을 작성해보는 'Human-First Thinking' 타임을 도입했고, 팀 차원에서 기초 CS 및 백엔드/프론트엔드 아키텍처 스터디를 정례화하여 AI의 추천을 맹목 수용하지 않고 능동적으로 지휘할 수 있는 역량을 키웠습니다."

### Q3. "Thymeleaf SSR 환경에서 FOUC 0.5초 문제를 어떻게 발견하고 극복하셨나요?"
* **🎤 모범 답변:**
  > "AI는 단일 파일 안에서 동작하는 코드를 선호하는 경향이 있어, Thymeleaf라는 서버 템플릿 엔진이 존재함에도 빈 HTML을 리턴한 뒤 client-side AJAX 통신만 남발하는 CSR 방식을 무분별하게 양산했습니다. 이로 인해 초기 진입 시 0.5초간 화면이 텅 비는 FOUC 현상이 발생했음을 발견했고, 개발자가 렌더링 아키텍처 주도권을 쥐고 Thymeleaf `th:each` 사전 바인딩(SSR)으로 전환하여 초기 진입 지연을 0ms로 완벽히 해결했습니다."
