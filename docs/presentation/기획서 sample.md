# Shinhan Delivery 프로젝트 기획서

## 1. 프로젝트 개요

### 1.1 프로젝트명
Shinhan Delivery

### 1.2 프로젝트 소개
Shinhan Delivery는 사용자가 배송 요청을 등록하고, 배송원이 이를 수락하여 실시간으로 배송을 수행할 수 있도록 지원하는 온디맨드 배송 서비스입니다.  
서비스는 단순 배송 요청 기능에 그치지 않고, 포인트 기반 결제, 배송 상태 추적, 취소/환불 정산, 배송원 보상, 관리자 승인 기능까지 포함하는 통합형 구조로 설계되었습니다.

### 1.3 기획 목적
기존의 단순 배송 요청 서비스는 요청 생성과 매칭까지만 구현되는 경우가 많아 실제 운영에 필요한 결제, 취소, 환불, 실시간 추적, 자격 검증 같은 요소가 부족한 문제가 있습니다.  
본 프로젝트는 이러한 한계를 보완하여 다음 목표를 달성하는 것을 목적으로 합니다.

- 사용자와 배송원을 분리한 역할 기반 서비스 제공
- 거리, 무게, 물품 크기를 반영한 배송비 자동 산정
- 앱 내 포인트 기반 결제 및 환불 처리
- 배송 진행 상태의 실시간 추적
- 배송원 승인 및 운영 관리 기능 제공

## 2. 서비스 목표

### 2.1 사용자 목표
- 배송 요청을 간단하고 빠르게 등록할 수 있어야 한다.
- 배송비를 사전에 확인하고 포인트로 쉽게 결제할 수 있어야 한다.
- 배송 진행 상태와 위치를 실시간으로 확인할 수 있어야 한다.
- 취소, 환불, 배송 완료 증빙을 신뢰할 수 있어야 한다.

### 2.2 배송원 목표
- 자신의 운송수단 조건에 맞는 배송 요청만 확인할 수 있어야 한다.
- 주문 수락과 배송 수행 과정을 직관적으로 처리할 수 있어야 한다.
- 고객 취소 시 보상 정책이 명확해야 한다.

### 2.3 운영 목표
- 회원, 배송원, 차량, 배송, 결제, 알림 정보를 통합적으로 관리할 수 있어야 한다.
- 배송원 자격 승인 및 증빙 검수 프로세스를 지원해야 한다.
- 결제 및 배송 이력을 추적할 수 있어야 한다.

## 5. 사용자 시나리오

### 5.1 고객 배송 요청 시나리오
1. 사용자가 회원가입 또는 로그인한다.
2. 포인트 지갑이 자동 생성된다.
3. 사용자가 결제 PIN을 설정한다.
4. 출발지, 도착지, 물품 정보, 요청사항을 입력한다.
5. 시스템이 서버 기준으로 배송비를 계산한다.
6. 사용자가 포인트로 결제를 진행한다.
7. 결제가 완료되면 배송 요청이 생성된다.
8. 조건에 맞는 배송원에게 요청이 전달된다.
9. 배송원이 주문을 수락한다.
10. 사용자는 배송 상태와 위치를 실시간으로 확인한다.
11. 배송 완료 후 완료 사진을 통해 결과를 확인한다.

### 5.2 배송원 수행 시나리오
1. 배송원이 회원가입한다.
2. 장비 및 자격 정보를 등록한다.
3. 관리자 승인 후 활동 가능 상태가 된다.
4. 반경 내 주문 목록을 조회한다.
5. 적합한 주문을 수락한다.
6. 픽업 완료 후 사진을 등록한다.
7. 배송 완료 후 증빙 사진을 등록한다.
8. 주문 완료 후 차량은 다시 가용 상태가 된다.

### 5.3 고객 취소 시나리오
1. 고객이 배송 취소를 요청한다.
2. 시스템이 현재 상태를 기준으로 환불 금액을 계산한다.
3. 필요 시 취소 수수료를 차감한다.
4. 배송원 보상이 필요한 경우 함께 처리한다.
5. 배송 상태를 취소로 변경한다.

## 6. 도메인 설계

회원 정보를 관리하는 도메인

주요 속성:
- email
- password
- name
- phoneNumber
- role
- pinHash
- pinFailCount
- pinLocked
- courierApprovalStatus
- proofDocumentUrl

### 6.2 Vehicle
배송원이 사용하는 운송수단 정보를 관리하는 도메인

주요 속성:
- memberId
- name
- type
- maxWeight
- maxDistance
- location
- status
- approvalStatus
- isActive

### 6.3 DeliveryRequest
배송 요청 정보를 관리하는 핵심 도메인

주요 속성:
- memberId
- pickupAddress
- dropoffAddress
- pickupLocation
- dropoffLocation
- weight
- distance
- feePoint
- status
- paymentIdempotencyKey
- pickupPhotoUrl
- proofPhotoUrl
- cancellationFee
- refundAmount
- courierCompensation

주요 상태:
- REQUESTED
- MATCHED
- PICKED_UP
- COMPLETED
- CANCELLED

### 6.4 Matching

주요 속성:
- deliveryRequestId
- vehicleId
- matchedAt
- status

### 6.5 PointWallet

주요 속성:
- memberId
- balance
- version

### 6.6 PointHistory
포인트 충전, 사용, 환불, 보상 이력을 기록하는 도메인

주요 속성:
- memberId
- walletId
- amount
- balanceAfter
- type
- paymentMethod
- idempotencyKey
- referenceId
- description

### 6.7 Notification
회원별 알림을 관리하는 도메인

주요 기능:
- 알림 목록 조회

## 8. 주요 정책

### 8.1 인증 및 권한 정책
- JWT 기반 인증을 사용한다.
- 사용자 역할에 따라 접근 가능한 기능을 구분한다.
- 본인 소유 데이터만 조회 및 수정 가능해야 한다.

### 8.2 배송비 산정 정책
배송비는 서버에서 직접 계산한다.

산정 기준:
- 기본요금: 3000
- 거리 할증: km당 500
- 무게 할증: kg당 200
- 크기 할증:
  - SMALL: 0%
  - MEDIUM: 30%
  - LARGE: 60%

### 8.3 결제 정책
- 결제는 포인트 기반으로 이루어진다.
- 회원가입 시 포인트 지갑이 자동 생성된다.
- 결제 시 PIN 검증이 필요할 수 있다.
- 동일 요청은 Idempotency-Key를 통해 한 번만 처리한다.
- 잔액 부족 시 결제를 차단한다.

### 8.4 배송 수락 정책
- 배송원만 배송 요청을 수락할 수 있다.
- 차량 적재 가능 무게와 최대 거리 조건을 만족해야 한다.
- 하나의 요청은 한 명의 배송원만 수락 가능하다.
- 하나의 차량은 동시에 여러 요청을 수행할 수 없다.

### 8.5 상태 전이 정책
- REQUESTED -> MATCHED
- MATCHED -> PICKED_UP
- PICKED_UP -> COMPLETED
- REQUESTED / MATCHED -> CANCELLED

### 8.6 취소 및 환불 정책
- REQUESTED 상태 취소 시 전액 환불 가능
- MATCHED 상태 취소 시 취소 수수료 부과 가능
- 배송원 이동 보상이 필요한 경우 별도 정산 처리
- 환불 및 보상은 이력으로 남겨야 한다.

### 8.7 보안 정책
- 결제 PIN은 해시로 저장한다.
- PIN 3회 실패 시 잠금 처리한다.
- 결제 및 포인트 차감은 서버 기준으로 검증한다.

### 8.8 동시성 및 안정성 정책
- 포인트 지갑 갱신 시 락을 사용한다.
- 주문 수락 시 배송 요청과 차량 상태를 안전하게 갱신한다.
- 멱등 키로 중복 결제를 방지한다.
- 상태 전이는 허용된 흐름에서만 가능하다.

## 12. 결론

Shinhan Delivery는 배송 요청, 배송원 매칭, 포인트 결제, 실시간 추적, 취소/환불, 관리자 운영 기능을 하나의 흐름으로 통합한 온디맨드 배송 서비스입니다.  
본 프로젝트는 단순 CRUD 수준을 넘어, 실제 서비스 운영에서 필요한 정합성, 보안성, 동시성 제어, 역할 기반 접근 통제를 고려하여 설계되었습니다.
