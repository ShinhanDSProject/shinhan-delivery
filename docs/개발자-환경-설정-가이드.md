# 로컬 개발 환경 및 자동화 도구 사용 가이드 (Developer Environment Guide)

이 문서는 프로젝트에 반영되어 있는 다양한 자동화 도구(CI/CD, 코드 포맷터, 테스트 데이터 적재, API 문서화, Git 템플릿)의 목적과 사용 방법 및 로컬 설정 가이드를 정리한 것입니다. 모든 팀원과 교육생은 가이드에 따라 로컬 설정을 완료해 주세요.

---

## 1. 🎨 코드 포맷 자동화 (Spotless & Google Java Style)
프로젝트의 소스 코드가 일관된 규격(Google Java Style 가이드)을 유지하도록 돕는 포맷터 도구입니다.

* **목적:** 팀원 간 스타일 규칙 조율 논쟁 최소화, 코드 가독성 극대화
* **적용 버전:** Spotless `6.25.0`, Google Java Format `1.28.0` (최신 JDK 호환)
* **로컬 사용법:**
  * 로컬 코드 스타일을 구글 규격에 맞춰 **자동 가공(포맷팅)**하려면 터미널에 다음 명령어를 입력합니다.
    ```bash
    ./gradlew spotlessApply
    ```
  * 코드 작성 완료 후 커밋 및 푸시하기 전에 한 번씩 실행하는 것을 강력히 권장합니다.
* **CI 검증 연동:** PR 제출 시 깃허브 액션에서 자동으로 포맷팅 준수 여부(`spotlessCheck`)를 확인하며, 스타일이 맞지 않으면 빌드가 반려(Fail)됩니다.

### 🛡️ 커밋 전 포맷 검사 로컬 강제화 (Lefthook 연동)
로컬에서 실수로 포맷 가공을 누락하고 커밋하여 CI 빌드를 실패시키는 피로를 방지하기 위해 Git pre-commit hook인 **Lefthook**을 프로젝트 루트에 탑재했습니다.

* **1단계: 설치 방법 (본인의 OS 또는 개발 도구에 따라 1개만 실행):**
  * **macOS:** `brew install lefthook`
  * **Windows (Scoop):** `scoop install lefthook`
  * **Node/npm:** `npm install -g @evilmartians/lefthook`
  * **Python:** `pip install lefthook`
* **2단계: Git Hook 등록:**
  프로젝트 루트 폴더에서 아래 명령어를 1회 실행하여 훅을 등록합니다:
  ```bash
  lefthook install
  ```
  이후 자바 소스 코드를 수정한 뒤 `git commit`을 날리면 자동으로 백그라운드에서 `./gradlew spotlessCheck`가 기동됩니다. 스타일이 어긋난 부분이 있다면 커밋이 반려되므로, `./gradlew spotlessApply`로 코드를 자동 정형한 뒤 다시 커밋을 전송하시면 됩니다.

## 2. 🔌 Swagger를 활용한 API 문서 자동화 (Springdoc OpenAPI)
Controller 코드와 DTO에 명시한 자바 어노테이션 기반으로 API 명세를 브라우저에 실시간 렌더링하고 시뮬레이션할 수 있게 돕는 도구입니다.

* **목적:** 수동 마크다운 명세 대조에 따른 불일치 문제 해소, 프론트엔드 협업 생산성 향상
* **로컬 접속 경로:** 애플리케이션 기동(`./gradlew bootRun`) 후 브라우저에서 아래 URL로 접속합니다.
  * 👉 **URL:** [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html)
* **준수 사항:** API 컨트롤러 추가/수정 시, 클래스에 `@Tag`, 메서드에 `@Operation`, DTO 필드에 `@Schema` 어노테이션을 활용해 설명을 상세하게 추가해야 합니다.

## 🧬 3. 로컬 테스트용 더미 데이터 자동 적재 (Data Seeding)
로컬에서 개발 및 테스트를 진행할 때, 회원가입과 차량 정보 및 지갑 개설 작업을 수동으로 매번 진행하는 단순 반복 삽질을 없애기 위한 기능입니다.

* **목적:** 로컬 서버 재실행 및 DB 초기화 시 테스트를 위한 반복 작업 단축
* **활성화 방법:** 프로젝트 루트의 `.env` 파일에 아래 환경 변수를 추가하고 구동합니다.
  ```env
  DATA_SEED_ENABLED=true
  ```

### 로컬 관리자 계정 생성

관리자 공지사항 생성·수정·삭제 기능을 로컬에서 확인하려면 `.env`에 다음 값을 추가한다. 관리자 시드는 기본적으로 비활성화되며, 이메일과 비밀번호를 모두 지정한 경우에만 동작한다.

```dotenv
ADMIN_SEED_ENABLED=true
ADMIN_EMAIL=본인이_사용할_관리자_이메일
ADMIN_PASSWORD=충분히_긴_로컬_전용_비밀번호
```

서버를 시작하면 비밀번호를 BCrypt로 암호화하여 `ADMIN` 계정을 한 번만 생성한다. 같은 이메일의 관리자가 이미 있으면 아무것도 변경하지 않으며, 일반 회원이 같은 이메일을 사용 중이면 자동으로 권한을 승격하지 않고 시작을 중단한다.

> [!WARNING]
> 실제 비밀번호가 포함된 `.env`는 Git에 커밋하지 않는다. 운영 관리자 계정 생성에는 이 로컬 시더를 사용하지 않는다.
* **적용 결과 (자동 적재 더미 데이터):**
  * **화주 회원 1명:** `client@example.com` / `password123` / 포인트 **500,000원** 충전 지갑 개설 완료
  * **배송원 회원 2명:** `courier1@example.com`, `courier2@example.com` / `password123`
  * **배송 차량 2대:** `courier1` 소유 1.5톤 탑차(CAR) 1대, `courier2` 소유 오토바이(MOTORCYCLE) 1대
* **안전 장치:** 본 기능은 깃허브 액션(CI) 환경 및 실제 프로덕션 서버 환경에서는 테스트 오염을 막기 위해 가동되지 않도록 철저히 격리 설계되어 있습니다.

## 🤝 4. Git 커밋 메시지 템플릿 (.gitmessage) 연동
협업 컨벤션(Conventional Commits)을 준수할 수 있도록 깃 커밋 실행 시 서식 힌트를 자동으로 띄워주는 서식 파일입니다.

* **목적:** 명확한 깃 커밋 이력 추적 및 일관성 확보
* **로컬 등록 방법:** 저장소를 내려받은 직후, 로컬 저장소 터미널에서 다음 설정을 딱 한 번만 입력합니다.
  ```bash
  git config --local commit.template .gitmessage
  ```
* **사용 방법:** 설정 완료 후, 터미널에서 `git commit`을 실행하면 템플릿 힌트 주석들이 에디터 버퍼에 로딩되어 나타납니다.

## 🛠️ 5. 테스트 및 빌드 자동화 (GitHub Actions CI)
PR 생성 및 코드 추가 푸시 시, 변경 내역이 기존 빌드 및 유닛 테스트를 망가뜨리지 않는지 격리 가상 환경에서 사전 검증해 주는 자동화 배포 파이프라인입니다.

* **동작 방식:**
  * PR이 열리면 온디맨드로 **MariaDB 10.11 컨테이너**가 함께 기동됩니다.
  * 가상 환경에서 `./gradlew spotlessCheck`를 통해 코드 포맷을 우선 체크합니다.
  * 이후 `./gradlew build`를 실행하여 JUnit5 통합/단위 테스트 50여 개가 모두 통과하는지 검증합니다.
* **Gemini AI 코드 리뷰의 작동 수칙 (중요):**
  * **최초 1회 자동 실행:** PR이 **처음 오픈(Opened)** 또는 **다시 오픈(Reopened)**될 때 최초 1회 자동으로 Gemini AI 리뷰가 기동되어 의견을 남깁니다.
  * **수동 추가 리뷰 호출:** 이후 추가 수정 코드를 푸시할 때는 자동 코드 리뷰가 돌지 않아 API 할당량을 절약합니다. 수정을 완료하여 다시 AI 검사를 받고 싶다면, **PR 댓글 창에 `/review`라고 작성하여 등록**해 주세요.
* **동시성 최적화(Concurrency):** 동일 PR에 연속해서 새로운 커밋이 푸시될 경우, 기존에 돌고 있던 옛날 빌드/코드리뷰 Actions 작업을 자동으로 즉시 취소 처리하여 리소스 낭비 및 Gemini API Rate Limit 오류 발생을 원천 예방합니다.
