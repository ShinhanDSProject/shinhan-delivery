# 🕸️ 배송 도메인 상태 전이 그래프 명세서 (Delivery State Graph Design)

> **Shinhan Delivery 배송 주문 생애주기(Delivery Request Lifecycle) 상태 전이 그래프 및 동시성 제어 설계 명세서**

---

## 📌 1. 개요 및 목적
배송 서비스의 핵심 엔티티인 `DeliveryRequest` 및 `Matching`은 복잡한 비즈니스 로직과 여러 사용자의 동시 요청이 얽혀있는 영역입니다.
본 문서는 배송 주문의 불법 상태 변경을 차단하고 멱등성(Idempotency) 및 스레드 안전성을 사수하기 위해 **상태 전이 그래프(State Machine Graph)**를 명세합니다.

---

## 🗺️ 2. 배송 상태 전이 그래프 (State Transition Graph)

```mermaid
graph TD
    Node_Start["[시작] 고객 배송 요청"] --> State_Requested["1. REQUESTED (배송 요청 등록)"]
    State_Requested --> State_Matched["2. MATCHED (배송원 배정 완료)"]
    State_Matched --> State_PickedUp["3. PICKED_UP (물품 픽업 완료)"]
    State_PickedUp --> State_Completed["4. COMPLETED (배송 완료 & 정산 완료)"]

    State_Requested -- "고객 취소 요청" --> State_Cancelled["CANCELLED (취소됨)"]
    State_Requested -- "30분 미배정 / 전액 환불" --> State_Cancelled
    State_Matched -- "고객 취소 / 이동 보상" --> State_Cancelled

    State_Completed --> Node_End["[종료]"]
    State_Cancelled --> Node_End["[종료]"]
```

## 📋 3. 상태 전이 규칙 및 API 매핑 테이블

| 출발 상태 (From) | 목적 상태 (To) | 허용 조건 및 락 정책 | 관련 API / 이벤트 |
| :--- | :--- | :--- | :--- |
| `[시작]` | `REQUESTED` | 결제/지갑 잔액 검증 통과 시 | `POST /api/v1/deliveries` |
| `REQUESTED` | `MATCHED` | 배송원 수락 및 비관적 락(`PESSIMISTIC_WRITE`) 검증 통과 시 | `POST /api/v1/delivery-requests/{id}/catch` |
| `MATCHED` | `PICKED_UP` | 배정된 배송원이 픽업 완료를 확인할 때 | `PATCH /api/v1/delivery-requests/{id}/pickup` |
| `PICKED_UP` | `COMPLETED` | 배송 완료 사진 업로드 및 완료 처리 시 | `PATCH /api/v1/delivery-requests/{id}/complete` |
| `REQUESTED` / `MATCHED` | `CANCELLED` | 배송 픽업 전 고객 취소 요청 시 (환불·이동 보상 처리) | `DELETE /api/v1/delivery-requests/{id}` |
| `REQUESTED` | `CANCELLED` | 생성 후 30분 경과·배송 요청 락 확보·결제 포인트 전액 환불 성공 시 | `DeliveryTimeoutScheduler` |
| `REQUESTED` | `CANCELLED` | 고객 본인 취소·수수료 0P·결제 포인트 전액 환불 | `POST /api/v1/delivery-requests/{id}/cancel` |
| `MATCHED` | `CANCELLED` | 고객 본인 취소·최대 1,000P 배송원 이동 보상·잔액 환불 | `POST /api/v1/delivery-requests/{id}/cancel` |

## 🛡️ 4. 예외 및 불가능한 전이 규칙 (Forbidden Edges)

1. **상태 역전 금지 (No Backward Edge):**
   - `PICKED_UP` ➔ `REQUESTED` 또는 `COMPLETED` ➔ `PICKED_UP`과 같이 과거 상태로 되돌아갈 수 없습니다.
2. **완료 상태 전이 불가능 (Terminal State Lock):**
   - `COMPLETED` 및 `CANCELLED` 상태는 그래프의 최종 노드(Terminal Node)이며, 어떠한 경우에도 상태 변경이나 취소가 불가능합니다.
3. **동시성 락 제어 (Concurrency Control):**
   - 동일 배송 요청에 대해 여러 배송원이 동시 수락을 시도할 경우, `PESSIMISTIC_WRITE` (DB `SELECT ... FOR UPDATE`) 락을 거친 최우선 배송원 1명만 `REQUESTED` ➔ `MATCHED` 상태 전이에 성공하며 나머지는 `AlreadyMatchedException`을 응답받습니다.
   - 자동 타임아웃도 같은 배송 요청 행을 잠그므로 콜 수락과 경쟁할 때 먼저 락을 획득한 상태 전이만 성공합니다.
