## 1. AI 시대의 개발 패러다임 변화

과거에는 개발자가 코드를 **직접 한 땀 한 땀 작성하는 것(Code Writing)**이 핵심 업무였다면, AI 시대에는 **"AI가 고품질 코드를 작성하도록 판을 깔아주고, 검증하고, 디렉팅하는 것(Code Orchestration & Verification)"**으로 개발자의 역할이 변화하고 있습니다.

이를 가능하게 하는 3대 핵심 기둥이 바로 **프롬프트 엔지니어링**, **하네스 엔지니어링**, **피드백 루프**입니다.

---

## 2. 프롬프트 엔지니어링 (Prompt Engineering)

### 💡 개념
AI(LLM)에게 원하는 정답을 얻어내기 위해 **질문과 지시문(Prompt)을 구조화하고 최적화하는 기술**입니다.

### 🛠️ 초보자를 위한 4대 핵심 프롬프트 패턴

#### ① Persona / Role Pattern (역할 부여)
* **Bad:** "Spring Boot 회원가입 코드 작성해 줘."
* **Good:** "너는 10년 차 **Senior Java Back-end Architect**야. 보안과 아키텍처 규칙을 엄격히 준수하면서 Spring Boot 회원가입 로직을 작성해 줘."

#### ② Context Injection (문맥 주입)
AI는 우리 프로젝트의 규칙을 모릅니다. 따라서 지시하기 전에 **프로젝트의 규칙이나 컨벤션을 미리 제공**해야 합니다.
* **예시:** "우리 프로젝트는 Controller에서 Repository를 직접 호출할 수 없어. `code-convention.md`에 명시된 레이어드 아키텍처 규칙을 바탕으로 코드를 수정해 줘."

#### ③ Few-Shot Prompting (입출력 예시 제공)
AI에게 말로만 설명하는 것보다 **바람직한 예시 1~2개를 보여주는 것**이 10배 정확합니다.
* **예시:** 
  > "아래 예시처럼 커스텀 예외를 만들어 줘.
  > `[예시]` public class MemberNotFoundException extends BusinessException { ... }"

#### ④ Chain-of-Thought (CoT, 단계별 사고 유도)
AI가 한 번에 코드를 토해내면 환각(오류)이 발생하기 쉽습니다. **생각의 과정을 단계별로 거치도록 요구**하세요.
* **예시:** "바로 코드를 짜지 마. 먼저 **1) 구현할 클래스 목록**, **2) 데이터 흐름**, **3) 예외 처리 시나리오**를 먼저 정리해서 보여준 뒤, 내 승인이 떨어지면 코드를 작성해 줘."

## 3. 하네스 엔지니어링 (Harness Engineering)

### 💡 개념
**하네스(Harness)**는 AI가 자유롭게 코드를 짜더라도 **"절대로 프로젝트를 망가뜨리지 못하게 막아주고, 작성된 코드가 정답인지 안전하게 테스트해 주는 인프라/환경"**을 설계하는 엔지니어링입니다.

```
┌────────────────────────────────────────────────────────┐
│                   Harness Environment                  │
│                                                        │
│   ┌───────────────┐     ┌──────────────────────────┐   │
│   │ Context       │     │ Execution & Test         │   │
│   │ Harness       │     │ Harness                  │   │
│   │ (CLAUDE.md 등)│     │ (verify.sh / JUnit / DDL)│   │
│   └───────┬───────┘     └────────────▲─────────────┘   │
│           │                          │                 │
│           ▼                          │                 │
│   ┌──────────────────────────────────┴─────────────┐   │
│   │               AI Agent (LLM)                   │   │
│   └────────────────────────────────────────────────┘   │
└────────────────────────────────────────────────────────┘
```

### 🧱 하네스의 3가지 구성 요소

1. **Context Harness (문맥 하네스):**
   * AI가 참조하는 가이드북 파일 (`CLAUDE.md`, `.cursorrules`, `code-convention.md`).
   * AI가 코드를 작성할 때 따라야 할 규칙과 금지사항을 정의합니다.
2. **Execution & Test Harness (실행 & 테스트 하네스):**
   * 코드 포맷터(Spotless), 린터, 아키텍처 검사기(ArchUnit), 테스트 도구(`verify.sh`).
   * AI의 코드가 실제로 동작하는지 격리된 샌드박스에서 구동하고 결과를 측정합니다.
3. **Eval Harness (평가 하네스):**
   * 작성된 코드가 성능, 보안, 커버리지 기준을 충족하는지 자동 평가하는 체계입니다.

## 4. 피드백 루프 (Feedback Loops & Self-Healing)

### 💡 개념
하네스 검사에서 나온 **결과(성공/에러 로그)를 AI에게 다시 전달하여, AI가 스스로 코드를 수정(Self-Healing)하도록 만드는 순환 체계**입니다.

### 🔄 피드백 루프의 3가지 형태

```
[코드 생성] ──▶ [하네스 검사] ──▶ [에러 수집] ──▶ [AI 에러 재주입] ──▶ [자가 수정]
     ▲                                                                  │
     └──────────────────────────────────────────────────────────────────┘
```

1. **Immediate Local Feedback (로컬 즉시 피드백):**
   * 개발자/AI가 코드를 고친 후 로컬에서 `./scripts/verify.sh`를 구동해 3초 만에 결과를 확인하고 바로 고치는 루프.
2. **Human-in-the-Loop (사람 참여 피드백):**
   * AI가 제시한 설계안(Plan)이나 PR 코드를 사람이 리뷰하고 방향성을 바로잡아주는 루프.
3. **CI/CD Pipeline Feedback (지속적 통합 피드백):**
   * GitHub PR을 올리면 CI 서버와 AI 리뷰봇(Gemini Code Reviewer 등)이 자동으로 코드 스타일과 빌드를 검사해 피드백을 남기는 루프.

## 5. 에이전트 기반 개발 방법론 (Agentic Workflow & EDD)

### 🤖 1) 에이전트 워크플로우 (Agentic Workflow)
AI에게 "이 거대한 서비스 전체 다 만들어줘"라고 지시하면 100% 실패합니다. 
현대적 에이전트 개발 방식은 작업을 **4단계 루프(Plan $\rightarrow$ Act $\rightarrow$ Test $\rightarrow$ Refactor)**로 작게 쪼개서 수행합니다.

* **Plan (계획):** 어떤 파일들을 수정할지 명세 작성
* **Act (수행):** 한 번에 하나의 클래스/메서드만 작성
* **Test (검증):** 하네스 스크립트로 즉시 검증
* **Refactor (수정):** 에러가 있으면 수집 후 수정

### 🧪 2) 평가 기반 개발 (Eval-Driven Development, EDD)
과거의 TDD(테스트 주도 개발)가 AI 시대에 진화한 개념입니다.
1. 개발자가 먼저 **테스트 하네스(검증 케이스)**를 작성해 둡니다.
2. AI에게 **"이 테스트 하네스를 통과하는 코드를 작성해 줘"**라고 요구합니다.
3. AI는 테스트가 통과할 때까지 자가 치유 피드백 루프를 돌며 코드를 완벽하게 완성합니다.

## 6. 초보자를 위한 실전 LLM 협업 5단계 룰

AI와 함께 일할 때 다음 5가지 원칙만 기억하면 초보자도 시니어급 생산성을 낼 수 있습니다!

1. **작은 단위로 작업하기 (Small Batch):** 한 번에 하나의 기능, 하나의 클래스만 요청하세요.
2. **프로젝트 규칙 제공하기:** 지시할 때 관련 컨벤션 문서(`code-convention.md`)를 참고하게 하세요.
3. **검증 하네스 돌리기:** AI가 준 코드는 무조건 `./scripts/verify.sh`로 검증하세요.
4. **에러를 무서워하지 말기:** 에러가 나면 에러 메시지 전체를 복사해서 AI에게 그대로 돌려주세요 (자가 치유).
5. **최종 결정권은 사람에게:** AI의 코드 결과를Blindly 신뢰하지 말고, 하네스 검사를 통과했는지 확인한 뒤 커밋하세요.
